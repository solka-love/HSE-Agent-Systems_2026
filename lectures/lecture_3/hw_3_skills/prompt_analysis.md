# Skill: Анализ системного промпта

## Требуемые инструменты
- `list_github_tools` / `load_github_tool` / `call_github_tool` — получение текста промпта из репозитория
- `save_analysis` — сохранение результата

## Когда активировать
Этот skill активируется, когда нужно:
- Разобрать один системный промпт на составные части
- Понять структуру и приёмы prompt engineering, использованные в нём
- Выявить persona, ограничения, инструкции и формат вывода
- Оценить качество и полноту промпта

Один вызов навыка = один файл промпта. Если файлов несколько, навык применяется к каждому отдельно.

## Протокол действий

### Шаг 1. Получи текст промпта
1. Если не знаешь, каким инструментом читать файл, вызови `list_github_tools`.
2. Вызови `load_github_tool` для нужного инструмента (как правило, `get_file_contents`), чтобы узнать схему параметров.
3. Вызови `call_github_tool` с аргументами в виде JSON-строки. Для этого репозитория:
   `{"owner": "asgeirtj", "repo": "system_prompts_leaks", "path": "<путь из задачи>"}`

Никогда не выдумывай содержимое промпта. Если инструмент вернул ошибку, сообщи об этом и заверши работу — пустой анализ сохранять нельзя.

### Шаг 2. Собери метаданные
Определи: путь файла, вендора (папка), продукт (имя файла), примерный объём в символах.

### Шаг 3. Разбери структуру
Выдели смысловые секции в порядке их появления: определение роли, описание инструментов, правила безопасности, формат ответа, примеры и так далее. Для каждой секции — одна строка о её назначении.

### Шаг 4. Оцени по шести критериям
Каждый критерий оцени по шкале 1–5 и подтверди короткой цитатой (не длиннее одной строки) или пометкой «отсутствует».

| # | Критерий | Что искать |
|---|----------|-----------|
| 1 | **Role / Persona** | Кем объявлен ассистент, есть ли характер, тон, рамки идентичности |
| 2 | **Guardrails и ограничения** | Запреты, отказы, правила безопасности, обработка спорных запросов |
| 3 | **Few-shot примеры** | Демонстрации входа и выхода, образцы диалогов |
| 4 | **Chain-of-thought / рассуждение** | Требование думать перед ответом, планировать, проверять себя |
| 5 | **Output format** | Требования к разметке, длине, структуре ответа |
| 6 | **Работа с инструментами** | Описание tools, правила выбора и последовательности вызовов |

### Шаг 5. Сформируй анализ по шаблону
Используй шаблон из раздела «Формат вывода». Все заголовки обязательны и неизменны: по ним навык `analysis_report` собирает сравнительную матрицу.

### Шаг 6. Сохрани результат
Вызови `save_analysis(name, content)`:
- `name` — путь файла с заменой слеша на подчёркивание и без расширения, например `OpenAI/Codex.md` → `OpenAI_Codex`
- `content` — полный текст анализа

### Шаг 7. Отчитайся
Одним-двумя предложениями: какой промпт разобран и в какой файл сохранён анализ.

## Формат вывода

```markdown
# Анализ: <Вендор> / <Продукт>

## Метаданные
- **Путь:** <path>
- **Вендор:** <папка>
- **Продукт:** <имя файла без расширения>
- **Объём:** <N> символов

## Структура
1. <Название секции> — <назначение>
2. ...

## Persona
<2–3 предложения: кем объявлен ассистент, какой тон и рамки заданы>

## Оценка приёмов

| Критерий | Наличие | Оценка (1–5) | Подтверждение |
|----------|---------|--------------|---------------|
| Role / Persona | да/нет | N | <короткая цитата> |
| Guardrails | да/нет | N | <короткая цитата> |
| Few-shot | да/нет | N | <короткая цитата> |
| Chain-of-thought | да/нет | N | <короткая цитата> |
| Output format | да/нет | N | <короткая цитата> |
| Работа с инструментами | да/нет | N | <короткая цитата> |

**Итоговая оценка:** <среднее из шести, одна цифра после запятой> / 5

## Сильные стороны
- <приём, который стоит перенимать>

## Слабые места
- <что упущено или сделано плохо>

## Что заимствовать
- <конкретная формулировка или приём, пригодный для нового промпта>
```

## Типичные ошибки
- Пересказ промпта вместо его разбора. Нужен анализ приёмов, а не содержания.
- Длинные цитаты. Ограничивайся одной строкой на критерий.
- Оценка «5» по всем критериям. Если приём отсутствует, ставь низкий балл и пиши «отсутствует».
- Пропуск шага сохранения. Задача не выполнена, пока `save_analysis` не вернул подтверждение.
