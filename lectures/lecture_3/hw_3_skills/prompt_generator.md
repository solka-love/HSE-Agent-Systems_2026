# Skill: Генерация системного промпта

## Требуемые инструменты
- `read_report` — чтение сводного отчёта
- `save_report` — сохранение сгенерированного промпта

## Когда активировать
Этот skill активируется, когда:
- Сводный отчёт (навык `analysis_report`) уже сформирован
- Пользователь просит написать, сгенерировать или составить системный промпт для ассистента
- Нужно применить выявленные лучшие практики к новой предметной области

## Протокол действий

### Шаг 1. Загрузи лучшие практики
Вызови `read_report("analysis_report")`. Если отчёта нет, инструмент вернёт список доступных файлов: выбери подходящий или сообщи пользователю, что сначала нужен отчёт.

Выпиши из отчёта разделы «Лучшие практики» и «Рекомендации для нового промпта». Дальше опирайся на них, а не на общие представления о промптинге.

### Шаг 2. Определи целевого ассистента
Из запроса пользователя вытяни: предметную область, аудиторию, задачи ассистента, доступные ему инструменты, ограничения. Если чего-то не сказано, выбери разумный вариант сам и зафиксируй его в разделе «Допущения» финального ответа. Не задавай уточняющих вопросов: работа идёт без участия человека.

### Шаг 3. Спроектируй структуру
Промпт обязан закрывать все шесть критериев из `prompt_analysis`:
1. Role / Persona
2. Guardrails и ограничения
3. Few-shot примеры
4. Chain-of-thought / порядок рассуждения
5. Output format
6. Работа с инструментами

Если какой-то критерий для этой области неприменим, скажи об этом прямо и объясни почему.

### Шаг 4. Напиши промпт
Пиши на языке запроса пользователя, в повелительном наклонении, обращаясь к ассистенту на «ты». Конкретика важнее объёма: «отвечай не длиннее пяти предложений» лучше, чем «отвечай кратко». Добавь минимум один few-shot пример.

### Шаг 5. Обоснуй решения
Свяжи не менее трёх решений в промпте с конкретными пунктами отчёта.

### Шаг 6. Сохрани результат
Вызови `save_report("generated_prompt", content)`.

### Шаг 7. Отчитайся
Кратко: для какого ассистента написан промпт, какие практики применены, куда сохранён файл.

## Типичные ошибки
- Генерация «из головы», без чтения отчёта. Тогда навык бесполезен.
- Расплывчатые формулировки вместо проверяемых правил.
- Отсутствие few-shot примеров.
- Копирование чужого промпта целиком вместо переноса приёмов в новую область.
