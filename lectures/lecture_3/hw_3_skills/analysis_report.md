# Skill: Формирование аналитического отчёта

## Требуемые инструменты
- `list_analyses` — список сохранённых анализов
- `read_analysis` — чтение конкретного анализа
- `save_report` — сохранение отчёта

## Когда активировать
Этот skill активируется, когда:
- Анализ отдельных промптов (навык `prompt_analysis`) уже завершён
- Пользователь просит сводку, обзор, сравнение или итоговый отчёт по всем разобранным промптам
- Нужно выявить общие паттерны и лучшие практики перед генерацией нового промпта

## Протокол действий

### Шаг 1. Узнай, что есть
Вызови `list_analyses`. Если список пуст, сообщи пользователю, что сначала нужно выполнить анализ промптов, и заверши работу. Отчёт по пустому набору не составляется.

### Шаг 2. Прочитай все анализы
Для каждого имени из списка вызови `read_analysis`. Читай все файлы, а не выборку: отчёт должен опираться на полный набор.

Если файлов больше десяти, обрабатывай их частями по пять, накапливая данные для матрицы.

### Шаг 3. Собери сравнительную матрицу
Сведи оценки по шести критериям в одну таблицу: строка — промпт, столбец — критерий. Добавь столбец с итоговой оценкой.

### Шаг 4. Найди паттерны
Ответь на вопросы по данным матрицы, а не по общим соображениям:
- Какие приёмы встречаются почти везде? Это отраслевой стандарт.
- Какие встречаются редко? Это либо нишевое решение, либо общая слабость.
- Чем отличаются промпты с высокой итоговой оценкой от промптов с низкой?
- Есть ли различия между вендорами?

### Шаг 5. Сформулируй лучшие практики
Не менее пяти пунктов. Каждый пункт опирается на конкретный промпт-источник, а не на здравый смысл.

### Шаг 6. Сохрани отчёт
Вызови `save_report("analysis_report", content)`. Имя файла именно такое: его ждёт навык `prompt_generator`.

### Шаг 7. Отчитайся
Кратко: сколько анализов агрегировано, какие главные выводы, куда сохранён отчёт.

## Формат вывода

```markdown
# Сводный отчёт по системным промптам

## Обзор
Проанализировано промптов: <N>. Вендоры: <список>.

## Сравнительная матрица

| Промпт | Role | Guardrails | Few-shot | CoT | Output format | Инструменты | Итог |
|--------|------|-----------|----------|-----|---------------|-------------|------|
| <имя>  | N | N | N | N | N | N | N.N |

## Распространённость приёмов

| Критерий | Присутствует | Средняя оценка |
|----------|--------------|----------------|
| Role / Persona | <k> из <N> | N.N |
| ... | | |

## Общие паттерны
1. <паттерн> — встречается в <промпты>
2. ...

## Лучшие практики
1. **<Название приёма>** — <в чём суть>. Источник: <промпт>.
2. ...

## Слабые места индустрии
- <что системно упускается>

## Рекомендации для нового промпта
- <что обязательно включить>
- <чего избегать>
```

## Типичные ошибки
- Отчёт по одному-двум анализам. Это не агрегация, предупреди пользователя о нерепрезентативности.
- Повтор содержимого анализов вместо сравнения. Ценность отчёта в сопоставлении.
- Выводы, не подкреплённые матрицей.
- Сохранение под произвольным именем: следующий навык ищет именно `analysis_report`.
