## Структура
1. **YAML frontmatter** — метаданные агента: имя (`claude`), область применения (catch-all), флаг `appendSystemPrompt: true`
2. **Контекст сессии** — описание, что сессия работает как фоновая задача; пользователь может быть офлайн; классификатор читает только текст сообщения
3. **Narrate** — требование одной строкой описывать подход перед действием и сообщать результат после каждого шага
4. **Restate** — требование пересказывать результаты своими словами (экстрактор не видит вывод инструментов); пересказывать реплики пользователя
5. **Subagent** — для шумных исследований (grep, логи, поиск) порождать суб-агента, оставляя только выводы
6. **Completed** — протокол завершения: сначала sanity check, затем маркер `result:` с однострочным заголовком
7. **Needs input** — протокол запроса: только когда одно действие человека разблокирует работу, иначе — предполагать и работать дальше
8. **Failed** — протокол отказа: `failed:` с причиной, когда задача структурно невыполнима
9. **Everything else** — общее правило: продолжать работу

## Persona
Ассистент представлен как фоновый агент (background job), работающий независимо от присутствия пользователя. Тон — сугубо деловой, технический, без эмоциональной окраски. Основная рамка — агент для CLI-среды (FleetView), который выполняет задачи молча и эффективно, сигнализируя о состоянии через строгие маркеры.

## Сильные стороны
- **Строгий протокол завершения/отказа.** Маркеры `result:`, `needs input:`, `failed:` на отдельной строке — это образец чёткого machine-readable формата, который позволяет классификатору отслеживать состояние задачи без разбора всего текста.
- **Принцип «предполагай и работай».** Если есть разумное предположение — делай его, отмечай допущение и продолжай. Это минимизирует холостые циклы ожидания.

## Слабые места
- **Нет few-shot примеров.** Промпт целиком состоит из инструкций, но не содержит ни одного образца диалога или демонстрации корректного/некорректного поведения.
- **Слабая персона.** Роль определена функционально (background job), но нет характерного тона, голоса или стиля общения.
- **Инструменты описаны поверхностно.** Упоминается только Agent tool / subagent, без спецификации других доступных инструментов и правил их выбора.

## Что заимствовать
- **Система маркеров состояния** (`result:`, `needs input:`, `failed:`) — компактный и надёжный способ передачи статуса задачи между агентом и классификатором. Пригоден для любого промпта, где требуется отслеживание выполнения.
- **Правило «предполагай вместо ожидания»** — «If a reasonable guess exists: make it, note the assumption, keep working» — снижает latency и количество итераций.
