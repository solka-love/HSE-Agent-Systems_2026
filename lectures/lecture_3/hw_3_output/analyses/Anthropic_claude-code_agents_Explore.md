## Persona
Ассистент объявлен «file search specialist for Claude Code» — специалистом по навигации и исследованию кодовой базы. Тон сугубо функциональный, без эмоциональной окраски или заданного характера. Persona сводится к роли read-only поискового инструмента: никакой креативности, только эффективный и быстрый поиск.

## Сильные стороны
- **Эталонные guardrails для read-only агента.** Блок «CRITICAL: READ-ONLY MODE» содержит исчерпывающий перечень конкретных запретов (создание, модификация, удаление, перемещение, временные файлы, redirect-операторы) — отличный шаблон для любого агента, которому запрещено изменять состояние.
- **Чёткое разделение инструментов по назначению.** find — для имён файлов, grep — для содержимого, Read — для конкретных путей. Каждый инструмент привязан к конкретному сценарию использования.
- **Адаптация под разные среды.** В комментарии описано, что для macOS/Linux используются find/grep через Bash, а для Windows — PowerShell-эквиваленты, и для сборок без встроенного поиска — Glob/Grep-инструменты.

## Слабые места
- **Нет few-shot примеров.** Промпт не содержит ни одного примера поискового запроса и ожидаемого ответа, что снижает предсказуемость вывода.
- **Нет chain-of-thought.** Агент не инструктируется планировать поиск, выбирать стратегию или проверять результаты — только требование «быть быстрым».
- **Нет формата вывода.** Отсутствуют требования к структуре отчёта: непонятно, должен ли агент группировать результаты, использовать списки, указывать пути и т.д.

## Что заимствовать
- Блок «CRITICAL: READ-ONLY MODE — NO FILE MODIFICATIONS» с конкретным перечислением запрещённых операций — готовый шаблон guardrails для любого read-only агента.
- Принцип «список разрешённых Bash-команд» (ls, git status, git log, git diff, find, grep, cat, head, tail) — чёткое отделение безопасных команд от опасных.
